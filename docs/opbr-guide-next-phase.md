# OPBR Guide 次フェーズ計画

既存の基礎改善後に残る作業を、コンテンツ整備、データ基盤、更新運用、将来機能の順に進める。目標は、初期整備を一度完了させた後、日常運用を「新情報入力 → AIへの更新指示 → 更新・テスト → 人間による最終確認」の短いサイクルへ移行すること。

## 優先順位

1. **Medal Sets**：主要セット、用途、代替候補を整理し、Character Guideから参照できる状態にする。
2. **Beginner Guide**：初心者が最初に必要とする基礎情報と、既存機能への導線をまとめる。
3. **Character Master schema**：大量入力の前に必要項目、ID、slug、画像、参照関係を確定する。
4. **既存データを埋める**：確定したschemaに合わせ、Character、Medal、Scoutの不足値と表記揺れを解消する。
5. **翻訳パイプライン**：日本語原稿を原本として、英語化・レビュー・実装を再現可能にする。
6. **SEOの仕上げ**：サイト名、Bing、metadata、構造化データ、sitemap、canonical、内部リンクを確認する。
7. **共有・コミュニティ機能**：Tier List共有から始め、投票、構造化投稿、コメントの順で段階的に追加する。

## 1. 一度作ればほぼ終わるコンテンツ

- Medal Setsページを作成し、主要セット、目的別分類、代替Medal、既存タグの不足を整理する。
- Beginner Guideを作成し、序盤の進め方、育成、編成、Medal、Scoutなどの入口をまとめる。
- 準備中ページは、公開コンテンツを追加するか、統合・削除するかを決める。公開までは既存の `noindex, follow` を維持する。
- Character固有ページの共通フォーマットを確定する。Overview、Strengths、Weaknesses、Skills、How to Play、Matchups、Medal Setsなど、必要なセクションを揃える。

これらは先に型を決め、後から全件を作り直さないことを重視する。

## 2. データ基盤とSource of Truth

Character、Medal、Scoutごとに原本となるデータを一つに定め、同じ情報を複数箇所へ手入力しない。

- Character Masterの最終schemaを確定し、`id`、`name`、`image`、`grade`、`element`、`role` に加えて、ガイド、Medal Sets、検索、SEOで必要な項目を洗い出す。
- ID、slug、名前、画像パス、タグの命名規則を統一する。
- Character、Medal、Scout間の参照は安定したIDで結び、一覧や派生情報は原本データから生成する。
- 必須値、重複ID、不正な参照、存在しないアセット、期間や確率の入力をvalidationで検査する。
- 新規Character、Medal、Scoutの追加手順を文書化し、更新後に実行するテストを統一する。

ゲーム内数値やScout確率は、公式情報を確認できたものだけを修正する。既存値を推測で補完しない。

## 3. 日本語原稿から英語コンテンツを作る

日本語原稿をSource of Truthとして残し、英語版はそこから生成・編集する。

1. 共通テンプレートに沿って日本語原稿を完成させる。
2. セクション単位で英語圏向けの自然な攻略記事へ変換する。
3. 記事全体の用語、文体、重複、長さを統一する。
4. 気になる英語表現を日本語原文と照合する。
5. 実装後にvalidation、lint、test、build、必要な画面確認を行う。

翻訳ルールは別途スタイルガイドにまとめる。情報を追加・削除しない、意味を変えない、冗長な箇所は圧縮する、OPBR固有用語を統一する、という原則を含める。日本語原稿は英語版の公開後も削除しない。

## 4. 将来のプロダクト機能

### Tier List共有

- ローカル保存
- 画像生成とダウンロード
- 共有URLとSNS共有
- 他ユーザーのTier Listをコピーして編集
- サイト内投稿

まず保存・画像生成・共有URLの仕様を決める。サイト内投稿以降は認証、DB、公開範囲、削除方針が必要になる。

### コミュニティ機能

- CharacterやScoutへの投票
- 新キャラクターの環境入り予測
- ScoutのPull / Skip投票
- Strengths / Weaknessesなどの構造化投稿
- 自由コメント
- Favorites、Recently Viewed、サイト内検索
- Character comparison、Meta Hub

導入順は **投票 → 構造化投稿 → 自由コメント** を基本とする。投稿・コメントを始める前に、認証、モデレーション、通報、編集・削除、スパム対策、データ保持方針を決める。

## 5. SEOとサイトの仕上げ

- Google検索結果のサイト名がVercel等の意図しない表記になっていないか確認し、site name、metadata、WebSite構造化データを整える。
- Bing Webmaster Toolsの登録、所有権確認、sitemap送信、クロール状況を確認する。
- 全公開ページのtitle、description、canonical、OG情報、sitemap掲載を確認する。
- 未完成ページは公開可能になるまでnoindexを維持する。
- Character固有ページをProgrammatic SEOの中心にし、Character、Guide、Medal Sets、Tier、Scout間の内部リンクを強化する。
- 必要に応じて動的OG画像を追加する。

## 6. 運用モデルへの移行

初期整備後は、所有者が新しい日本語情報と確認済みデータを入力し、AIが既存schemaとスタイルガイドに沿って実装する。

> 新情報入力 → AIへの更新指示 → 更新・テスト → 人間による最終確認

AIは翻訳、データ反映、派生ページ更新、validation、回帰テストまでを担当する。人間はゲーム内事実、数値、ニュアンス、公開可否を最終確認する。公式確認できない情報は推測で確定せず、保留事項として明示する。

定型の更新指示は、最終的に次の程度まで短くする。

> この日本語Character Guideと確認済みデータを、既存schemaとスタイルに合わせて英語化・実装し、関連ページを更新してテストしてください。

## 完了条件

- Medal SetsとBeginner Guideが公開可能な内容になっている。
- Character固有ページの型とCharacter Master schemaが確定している。
- Character、Medal、ScoutのSource of Truthと追加手順が明文化され、validationで参照不整合を検出できる。
- 日本語原稿から英語公開までのテンプレート、用語、レビュー手順が再利用できる。
- SEOの主要設定と検索エンジン向け登録が確認済みである。
- 通常更新が上記の運用サイクルだけで完結し、人間の作業が事実確認と最終承認に集中している。
